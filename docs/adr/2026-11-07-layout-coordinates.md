# One coordinate system for the three levels, discs sized by Size

Every Module carries a frozen position (X, Y) and a Radius in one map coordinate system shared by Packages, Directories and Files. A Module's Radius is `sqrt(max(Size, 1)) × 0.8^depth` (depth 0 for Packages, 1 for Directories, 2 for Files), so a disc's area is proportional to Size and the children of a Module, whose Sizes add up to the parent's, fill about two thirds of the parent's disc. Packages are laid out among themselves around the origin; the Directories of a Package inside the Package's disc; the Files of a Directory inside the Directory's disc. Zooming into a Module therefore reveals its children inside and around it, without any per-level transform in the UI.

The layout is a force relaxation (collisions, Dependency springs, gravity, a bound to the parent's disc) started from a sunflower spiral, per group of siblings, with a bounded number of iterations and collisions found through per-size-class grids, so its cost is roughly linear in the number of Modules. Positions are stored in the index by Module ID and never deleted: Modules that leave the Map keep their last position (ghosts in a Comparison), and new Modules are relaxed around the frozen ones. Radii follow the current Size, so a Module that grows a lot may come to overlap its neighbours; re-laying out would move everything, which the frozen Map rules out.

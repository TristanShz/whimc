# The index is keyed by git blob hash, in a SQLite file in the user cache

Every per-File analysis result (imports, Complexity, lines of code) is stored in SQLite under the hash of the File's git blob; working-tree files are hashed the same way (`git hash-object`). A Comparison between two states only parses the blobs the index has never seen, which is what makes comparing commits on a 10M+ LOC repository cheap. The database lives in the user cache (`~/Library/Caches/whimc/<repo hash>/index.db` on macOS), not in the repository, so it never pollutes the working tree and every worktree of the same repository shares it — AI agents use many worktrees. SQLite over an embedded key-value store because the index must stay queryable ad hoc and move to a server when the hosted version comes.
